# Konfigurátor na produktové stránce - tvar dat, který UI (bot16) očekává

Navrhuje bot16 podle dohody s bot5/bot10 (jeden veřejný `resolve`, model dojíždí podle téhož `hash`). Co je jinak, opravte,
UI se přizpůsobí. Všechny texty česky, bez interních názvů, ID voleb neprůhledná.

## 1) příznak u produktu
`GET /api/shop/products/<id>` -> `product.configurator = {"available": true, "default_view": "turntable"|"configurator"}`
(chybí = stránka beze změny; rozhoduje `is_live_3d_assembly` na serveru, stránka nic neodvozuje).

## 2) schéma
`GET /api/shop/products/<id>/configurator`
{
  "rules_version": "2026-10-02.1",
  "groups": [{"id": "g_deska", "label": "Deska"}],
  "slots": [{
     "id": "s1", "group": "g_deska", "label": "Barva desky", "help": null,
     "type": "chips" | "swatch" | "select" | "toggle" | "slider",
     "options": [{"id": "o1", "label": "Dub", "swatch": "#c8a165"}],          // chips/swatch/select/toggle
     "slider": {"min": 600, "max": 1800, "step": 10, "unit": "mm"},           // jen type=slider
     "g": 3                                                                    // volitelné neprůhledné číslo skupiny uzlů (onPick)
  }],
  "default_selection": {"s1": "o1", "s2": 1200, "montaz": false}
}
Montáž je obyčejný slot `montaz` (type toggle, option „Montáž" s price_delta v odpovědi resolve), stránková karta
voleb montáže se u konfigurátoru skryje.

## 3) resolve (jediný veřejný endpoint pro cenu, stavy a model)
`POST /api/shop/configurator/resolve`  {"product_id": 1, "selection": {...}, "rules_version": "…"}
200 {
  "selection": {...normalizovaný výběr (server ořízne hodnoty)...},
  "hash": "9f3c…", "kod": "STL-4F2A91", "rules_version": "…",
  "valid": true, "errors": [{"slot": "s3", "message": "Tuhle kombinaci nelze vyrobit."}],
  "price": {"net": 12345.0, "vat_rate": 21, "gross": 14937.45, "currency": "CZK"},
  "options": {                      // stavy voleb PRO TENTO výběr
     "s1": {"o1": {"price_delta": 0, "disabled": false, "reason": null}, "o2": {"price_delta": 1240, "disabled": true, "reason": "S touto deskou nejde zvolit…"}},
     "s2": {"min": 600, "max": 1500}      // slider: aktuální meze
  },
  "model": {"stav": "hotovo" | "pripravuje_se" | "chyba", "url": "…krátce platný odkaz…", "odhad_ms": 4000, "kod": null}
}
Chyby: 429 (Retry-After), 409 `{"error": "rules_changed"}` (pravidla se změnila -> UI znovu načte schéma), 4xx/5xx `{"error": "…"}`.
`GET /api/shop/configurator/model/<hash>` -> `{"model": {...}}` (stejný tvar, UI se ptá, dokud stav není hotovo/chyba).

## 4) košík
`POST /api/cart/items` {"product_id", "qty", "configuration": {"selection": {...}, "hash": "…", "rules_version": "…"}}
odpověď nese cenu a `kod`. Řádek se zastaralou/neplatnou konfigurací vrací příznak `invalid_configuration`
(UI: „Zvolte konfiguraci znovu", do pokladny nepustí). Cenu klient neposílá.

## Jazyk (doplněno 2026-10-02, bot16 + bot8)
Modul (`ctx.lang`) posílá `?lang=cs|en` u schématu a `lang` v těle `resolve`; server vrací texty voleb v tom jazyce (bot8: `api/stul_shop.py`). Bez `lang` = výchozí jazyk serveru. Texty samotného UI (tlačítka, hlášky) dodává stránka přes `ctx.labels`, texty 3D prohlížeče přes `ctx.viewerLabels`.

## Oznámení, nabídky a návrhy (doplněno 2026-10-02, bot8 + bot16; rules_version 2026-10-02.5)
- `resolve.selection` je EFEKTIVNÍ výběr (server sám odebral nevejdoucí příslušenství); `resolve.notices[]` = `{slot, action:"removed", message}` → UI je ukáže zákazníkovi (blok `pdc-notices`).
- Kolize po posunu (šuplíky, střední noha) se sama neodebírá: `valid:false` + `resolve.offers[]` = `{slot, action:"remove", label, message}`; po kliknutí UI pošle výběr s tímto slotem `false`.
- Zakázaný přepínač, který jde povolit změnou rozměru: `options.<slot>.on` = `{disabled:true, reason, suggest:{w|d:mm}, suggest_label}`; UI nabídne tlačítko `suggest_label` a po kliknutí pošle výběr s novým rozměrem a slotem zapnutým.
- ~~`resolve.vodici.stredni_noha`~~ → modul voleb ho od 2026-10-04 NEPOUŽÍVÁ (vlastní velký úchyt střední nohy smazán, bot16): střední nohu táhne obecná ikona z `vodici.ovladani.tahy` (`id:"mid"`, slot `mid` v %).

## Výřezy v pracovní desce (doplněno 2026-10-02, bot8; rules_version 2026-10-02.7)
Žádná změna typů slotů – jen nové sloty ve skupině `g_cuts` („Výřezy v pracovní desce“), pro `n` = 1…3:
- `cut<n>` (toggle) – výřez je v desce; výchozí vypnuto; `options.cut<n>.on.price_delta` je 0 (cena desky se výřezem nemění).
- `cut<n>w` (slider, mm) šířka otvoru podél stolu, `cut<n>d` hloubka otvoru od předu dozadu, `cut<n>x` vzdálenost otvoru od PŘEDNÍHO okraje desky, `cut<n>z` vzdálenost od LEVÉHO okraje desky (krok 10; výchozí w 200, d 150, x 100, z 100 + (n−1)·260).
- `options.cut<n>w/d/x/z` = {min, max} podle AKTUÁLNÍ desky: w 50…šířka−60, d 50…hloubka desky−60, x 30…hloubka desky−30−d, z 30…šířka−30−w (od okraje desky vždy aspoň 30 mm). U VYPNUTÉHO výřezu je min = max (posuvníky zamčené; UI je může schovat).
- Server otvor vždy ořízne na desku (zmenšení stolu otvor zmenší/posune, nikdy nevyleze); `resolve.selection` nese efektivní hodnoty.
- Dva otvory se nesmí překrývat ani být blíž než 30 mm: `valid:false`, `errors[{slot:"cut<n>", message}]` (n = pozdější z dvojice) a `offers[{slot:"cut<n>", action:"remove", label:"Odebrat výřez <n>"}]`; po kliknutí UI pošle výběr s `cut<n>:false`.
- Cena i košík: výřez se neúčtuje zvlášť, počítá se cena CELÉ desky. `model.url` nese výřezy (GLB je deska rozřezaná na obdélníky kolem otvorů, bez zvláštních uzlů). Vypnutý výřez se do `hash`/`kod` nepočítá (stejná konfigurace = stejný hash).
- Token odkazu na GLB nese výřezy v klíči `c` (pole `[w,d,x,z]` zapnutých, 0 = vypnutý); starší tokeny bez `c` = bez výřezů.

## Police pod výřezem a ložiskové jednotky (doplněno 2026-10-02, bot8; rules_version 2026-10-02.8)
Žádná změna typů slotů (toggle/slider); `rules_version` je 2026-10-02.8, starší hodnota = 409 `rules_changed`.
**Police pod výřezem** – slot `cut<n>shelf` (toggle, skupina `g_cuts`, n = 1…3, výchozí vypnuto):
- Police je o 40 mm na každou stranu větší než otvor, její horní plocha je 100 mm pod spodkem desky stolu; drží ji dva nosné profily zavěšené na předním a zadním rámu. Cena: `options.cut<n>shelf.on.price_delta` = skutečný rozdíl ceny (deska + profily).
- Bez zapnutého výřezu je přepínač zakázaný: `options.cut<n>shelf.on = {disabled:true, reason}`; `resolve.selection.cut<n>shelf` je `false`, i když ho klient poslal `true`. Vypnutý výřez se do `hash`/`kod` nepočítá ani s policí.
- Kolize (blízko okraje desky, noha, šuplíky, nízký stůl): `valid:false`, `errors[{slot:"cut<n>shelf", message}]` a `offers[{slot:"cut<n>shelf", action:"remove", label:"Odebrat polici pod výřezem <n>", message}]`; příslušenství se kvůli polici NIKDY neodebírá (jen nabídka odebrat polici – UI pošle výběr s `cut<n>shelf:false`, výřez zůstává).
**Ložiskové jednotky** (kuličkové, karta 3025) na pracovní desce – skupina `g_bearings`:
- `bearings` (toggle, výchozí vypnuto), `bearpitch` (slider, rozteč středů jednotek, 40…1000 mm, výchozí 200), `bearedge` (slider, vzdálenost jednotek od okraje desky, 30…500 mm, výchozí 100); krok 10. Jednotky tvoří mřížku vycentrovanou na desce; počet z roztečí vyplyne, jednotky v místě výřezu (a kolidující s jiným dílem) se vynechají.
- `options.bearings = {on:{price_delta, disabled, reason}, count:{placed, omitted}}`: `count.placed` = počet jednotek na desce (při vypnutém přepínači kolik jich zapnutím přibude), `count.omitted` = kolik pozic mřížky se kvůli otvoru/kolizi vynechalo; `price_delta` je skutečný rozdíl ceny (cena karty × počet). UI může ukázat „24 ks".
- Při vypnutém přepínači jsou posuvníky zamčené (`options.bearpitch/bearedge` min = max); vypnuté jednotky se rozteči/okrajem do `hash` nepočítají.
- Víc než 500 jednotek: `valid:false`, `errors[{slot:"bearpitch", message:"Příliš mnoho ložiskových jednotek …"}]`, `count.placed` 0 (zvětši rozteč nebo okraj).
- Token odkazu na GLB: `c[n]` může mít 5. prvek `1` (police pod výřezem), klíč `l` = `[rozteč, okraj]` (jen u zapnutých jednotek); starší tokeny bez nich = bez police a bez jednotek. Model jednotek je chromový a vyrábí se na serveru (stejně jako zbytek GLB, bez katalogových názvů).

## Posun šuplíků: přesné meze (doplněno 2026-10-03, bot8; Robert: „šuplík v noze je neakceptovatelný“)
`options.boxpos = {min, max, value, fits}` jsou PŘESNÉ meze posunu šuplíkového boxu z generátoru (`suplik_meze`): od každé nohy (krajní i střední) aspoň 30 mm, bez kolize s držákem PET lahve; po 10 mm, zaokrouhleno dovnitř. `value` = skutečný posun boxu (u užšího stolu s automatickým posunem se liší od vybraného `boxpos` 0), `fits:false` = box se nevejde (min = max = value). UI čte `options.boxpos.min/max` (dřívější hrubé −(šířka−700)…80 neplatí). Hodnota mimo meze se NEořezává tiše: vznikne kolize a nabídka „Odebrat šuplíky“ (`offers`), jako dřív u posunu do nohy.
Staff API: `suplik_meze {hodnota, min, max, vejde}` v odpovědi; 3D tah `suplik_posun` bere `hodnota`/`min`/`max` odtud. Test: `test_stul_suplik_meze.py` (světlá vzdálenost od všech nohou měřená ze skutečných sítí).

## Šikmé vzpěry ramen LED (doplněno 2026-10-03, bot8; rules_version beze změny – výchozí konfigurace a její hash se nemění)
Volitelná stabilizace při zatížení (Robert: „podepření rampy pro LED“): pod každým ramenem LED šikmá vzpěra 45° mezi zadní stojkou a ramenem (profil zvolené délky, na obou koncích šikmé spojky; délku vzpěry určuje délka profilu). Skupina `g_extras`:
- `braces` (toggle, výchozí vypnuto) a `bracelen` (slider, délka PROFILU vzpěry 100…1000 mm po 10, výchozí 300; `options.bracelen = {min, max}` jsou PŘESNÉ meze pro aktuální stůl – při vypnutém přepínači zamčené min = max). Parametry generátoru `vzpery`, `vzpera_delka`; staff odpověď nese `vzpera_meze {hodnota, min, max, vejde}` (jen u zapnutých vzpěr).
- `options.braces = {on:{price_delta, disabled, reason}}`: `price_delta` = skutečný příplatek (profil, řezy, spoje, 2× šikmá spojka na vzpěru); `disabled` + `reason`, když se vzpěry nevejdou (potřebují zadní stojky a LED, volné místo před stojkami a rameno LED aspoň ~200 mm). **Od 2026-10-05** perforovaný panel sedí MEZI zadními stojkami (v jejich rovině), vzpěry zakrývat nemůže – dřív „u užšího stolu pod ~1300 mm je zakrývaly panely“ už neplatí.
- Horní mez délky dává rameno LED (šikmá spojka u ramene musí celá ležet pod ramenem) a okolní díly (u výchozího ramene 560 mm je to 630 mm; u ramene 1000 mm a víc celých 1000 mm; u ramene 300 mm 260 mm). Požadovaná `bracelen` nad touto mezí se na ni ZKRÁTÍ (vzpěry zůstanou, `selection.bracelen` je skutečná délka, `options.bracelen.max` skutečná mez); UI má ukázat `options.bracelen` jako meze jezdce a pod ním řádek „Povoleno od … do … mm“. Vzpěry se samy odeberou jen když nejsou stojky/LED. Meze vznikají konzervativním AABB testem šikmých spojek (skutečná síť smí mít o pár mm víc místa).
- Zapnuté vzpěry, které se při změně rozměrů nebo volby nevejdou, se samy odeberou: `notices[{slot:"braces", action:"removed", …}]` a `selection.braces:false`. Chyby nejdou na slot `braces` jako technická hláška, ale s textem `DUVODY[lang].braces`.
- Cena a kusovník: profil vzpěry (délka = `bracelen`, řezy), 2× šikmá spojka 45° (30) na vzpěru, 2 spoje profilů na vzpěru. U stolu se střední NOHOU se přidá i střední vzpěra (+9 dílů místo +6; od 2026-10-05 i s panely, které sedí vedle stojky).
- Token modelu: bit „vzpery“ v `t` (bit 8) + klíč `v` (délka); vypnuté vzpěry token nemění. `hash`/`kod` vypnutých vzpěr se nemění.
- Ovládání ve 3D: část `braces` (pravé tlačítko: odebrat / delší +50 mm / kratší −50 mm), v nabídce LED „Přidat vzpěry ramen LED“.

## Stabilní funkce pro košík / objednávku / nabídku (bot8 pro bot5, 2026-10-02)

Server-side import, nezávislý na vnitřnostech (`resolve`, `normalizuj`, generátor se smějí přejmenovat): `from stul_shop import pro_objednavku, glb_bytes`.

- `pro_objednavku(selection, rules_version=None, lang="cs")` → **hluboká kopie** (volající ji smí měnit):
  `{ok:true, selection (EFEKTIVNÍ po automatickém odebrání), hash, kod, rules_version, valid, errors:[str], notices:[str], price:{net,vat_rate,gross,currency}|null, bom:[{nazev,mnozstvi,rozmer}], pocet_spoju, souhrn:[{id,label,value}]}`.
  `rules_version` jiná než aktuální → `{ok:false, chyba:"rules_changed", rules_version:<aktuální>}` (volající zavolá znovu bez ní a ukáže novou cenu). Neplatný výběr se ořízne a ohlásí v `valid`/`errors`, nevyhazuje.
  `bom` je neutrální (bez čísel dílů a dodavatelů): profily podle délky, desky podle rozměru, ostatní kusy; `souhrn` = čitelné shrnutí voleb (jen smysluplné: výřezy a jednotky jen když zapnuté, střední noha jen nad 1500 mm…).
- `glb_bytes(selection)` → GLB (`bytes`, z cache, nemění se) pro EFEKTIVNÍ výběr.
- `resolve()` teď také vrací hlubokou kopii (dřív sdílené vnořené slovníky s cache).
- Doplněno na žádost bot5: `hmotnost_kg` (součet hmotnosti dílů, které ji mají v katalogu), **`hmotnost_uplna`** (bool) a `hmotnost_chybi` (neutrální názvy dílů bez hmotnosti v katalogu) – dnes chybí laminodeska, šuplíky, LED, panely, elektrožlab, držák PET, kolečka a ložisková jednotka, takže `hmotnost_kg` jsou jen profily a spojky (výchozí stůl ~15 kg) a **pro dopravu nestačí**, dokud se hmotnosti nedoplní v katalogu. `cenovy_souhrn` = `stul_api.cena_konfigurace(...)["souhrn"]` (material_czk, cut_czk, joint_czk, accessory_czk, packaging_czk, joint_count, weight_kg), kopie.
- `konfigurovatelny(product_id)` → bool (produkt je konfigurovatelný stůl, `app_settings.configurator_products`); **stabilní**, signatura se nemění.

## Slovenčina a skrytá cena pro mini-shop (bot8 pro bot3/bot7, 2026-10-02)

- `lang=sk` (schema i resolve; `Accept-Language: sk…` také): všechny popisky, nápovědy, důvody, oznámení („Automaticky odstránené: …“), nabídky a názvy výřezů/jednotek ve slovenštině (texty bot7, doplněno `feet`, názvy slotů a akce – ke kontrole bot7). Veřejný text neobsahuje slovo „konfigurátor“, čísla dílů ani dodavatele (leak-scan v testu).
- **Skrytá cena** (mini-shop = jen dopyt): `resolve` s `"price": "hidden"` v těle (nebo `?price=hidden`) vrací odpověď BEZ ceny – zmizí `price` i `options.<slot>.on.price_delta`; vše ostatní (hash, kód, valid, errors, notices, offers, model) beze změny. **Skutečná ochrana je na serveru:** `app_settings.configurator_hide_price_hosts` = JSON seznam hostname mini-shopů (např. `["minishop.example.sk"]`); pro požadavky na tyto hosty se cena NIKDY nevrací, ať klient pošle cokoli (jinak by technický návštěvník stačil zavolat API bez parametru). Bez nastavení se hostům nic neskrývá (e-shop a zaměstnanci cenu dostávají). Nastavení je potřeba zapsat (sandbox blokuje zápis do app_settings botem – udělá Robert/bot3 přes `!` příkaz). `stul_shop.pro_objednavku` (server-side košík) cenu nese vždy.
- Aktualizace 2026-10-03: `hmotnost_kg` nově obsahuje i **laminodesky** ze skutečné plochy kusů (pracovní deska bez výřezů, spodní police, police pod výřezem) × 11,2 kg/m² (Robert: plech 2800 × 2070 mm ≈ 65 kg). `hmotnost_chybi` už laminodesku nevyjmenovává; zbývají šuplíky, perforovaný panel, LED, elektrožlab, držák PET, kolečko, ložisková jednotka → `hmotnost_uplna` zůstává `false`, dokud se nedoplní. `cenovy_souhrn.weight_kg` je dál jen katalogový součet (bez desek).

## Výrobní sestava (bot8 pro bot5, 2026-10-03)

Robert: *„generátory mají generovat sestavy, při objednání ukládat do DB, obsahovat kompletní výčet dílů aby se dalo vyrobit“* (výrobní výpis má navíc: desky s výřezy, spojovací materiál, montážní postup).
- `stul_shop.vyrobni_sestava(selection, rules_version=None, lang="cs")` → vždy nová kopie `{ok, selection, hash, kod, rules_version, valid, parametry (efektivní), dily (SNÍMEK: part_id, position, quaternion, scale, lic_peers, attached_to… jako custom_shapes.data.parts), vypis, kusovnik_katalog [{nazev (se SKU), rozmer, mnozstvi, cena_ks_czk, celkem_czk}], cena_celkem_czk, cenovy_souhrn, hmotnost_kg, hmotnost_uplna, hmotnost_chybi}`. Nevalidní konfigurace → `{ok:false, chyba:"invalid_configuration", errors}`, jiná verze pravidel → `{ok:false, chyba:"rules_changed"}`.
- `vypis`: `rezny_plan` [{delka_mm, pocet, id_dilu}], `desky` [{role, ks, tloustka_mm, sirka_mm, hloubka_mm, vyrezy [{n, sirka_mm, hloubka_mm, od_predniho_okraje_mm, od_leveho_okraje_mm}], id_dilu}] (pracovní deska s výřezy je JEDEN kus; spodní police; police pod výřezem), `prislusenstvi` [{karta_id, nazev, pocet, id_dilu}] (ložiskové jednotky navíc rozteč, od okraje, řady × sloupce, `polohy_stredu_mm` od předního/levého okraje desky), `rohove_spojky`, `spoje`, `spojovaci_material` (počty spojů a spojek; `typ_sroubu_a_matic: null` = zatím neurčeno, doplní Robert), `montazni_postup` [{krok, text, dily}] (návrh ke kontrole výrobou; kroky 2–9 dělí všechny díly právě jednou), `role_dilu`.
- **Doporučené uložení při objednání (bot5):** celý výsledek jako JSON k položce objednávky (neměnný snímek: jen tak lze starou objednávku vyrobit i po změně pravidel). Snímek `dily` jde otevřít ve Scéně (stejný formát jako vlastní tvary). `hmotnost_kg` je neúplná, dokud `hmotnost_uplna` není true.
- Zaměstnanci: `GET /api/stul/vyrobni-list?<parametry jako /api/stul/konfigurace>` = čitelný HTML výrobní list k tisku (řezný plán, výkres desky shora s výřezy a polohami jednotek, příslušenství, spojovací materiál, postup, kusovník s SKU a cenami); `GET /api/stul/vyrobni-sestava?…` = totéž jako JSON.


## Ovládání ve 3D (veřejná podoba, bot8 2026-10-03)
`resolve` vrací v `vodici` navíc `ovladani` (vedle `stredni_noha`, ten se nemění) – popis, co se dá ve 3D chytit a co nabídnout. Formát a chování modulu v prohlížeči:
`docs/OVLADANI_3D.md`; tady jen rozdíly veřejné podoby (`api/stul_ovladani_verejne.py`):
- místo názvů parametrů generátoru jsou **veřejné názvy slotů** (`w`, `d`, `h`, `cut1x`, `cut1shelf`, `boxpos`, `arm`…), místo indexů dílů `leg1…`, `legend1…`, `shelf1…`, `cut1…`; žádné číslo dílu ani `product_`/`Object_`;
- texty (`label`, `menu[].text`, `menu[].duvod`, `tahy[].label`, `mereni[].label`) jsou v jazyce požadavku (cs/en/sk); popis jednotek je anglicky v `units`;
- `nastav` pracuje se sloty (`{"cut2": true}`, `{"mid": 50}` = střední noha doprostřed, hodnota v %); `bod_na_desce` ukazuje na sloty `cutNx`/`cutNz` a `cutNw`/`cutNd`;
- střední noha: tah `mid` (slot `mid`, % mezi nohami, `jednotka:"%"`) je v popisu ovládání jako ostatní tahy (od 2026-10-04); `vodici.stredni_noha` zůstává v odpovědi jen pro starší klienty;
- chybí-li překlad nějakého textu, `ovladani` se vynechá a chyba jde do logu (resolve nespadne); test `test_stul_shop.py` hlídá úplnost překladů ve všech třech jazycích.

## Zavislosti slotu `depends_on` (bot8 2026-10-03, na zadost bot16 / Robert: „volba bez nadrazene zapnute volby neexistuje“)
`schema.slots[]` nese u slotu, ktery zavisi na jinych, pole `depends_on: [id slotu…]` (seznam toggle slotu; slot je platny/viditelny jen kdyz jsou VSECHNY zapnute – AND). Nezavisle sloty pole nemaji.
Neni-li nadrazena volba zapnuta, UI slot neukazuje (ani ve shrnuti vyberu), a server jeho hodnotu ignoruje (stejny model, hash i cena – hlida test_stul_shop.py).

## Spodní police při hloubce nad 900 mm: kratší deska + podpěry (bot8 2026-10-03, `rules_version` 2026-10-03.1)
Robertovo řešení konstrukce (dřív kolize desky police se svislým profilem bočnice): jakmile je hloubka > 900 mm (do každé bočnice přibývá svislý profil doprostřed), platí pro KAŽDOU spodní polici:
- **deska police je po šířce stolu o 62 mm užší** (31 mm = 30 mm profil + 1 mm vůle z každé strany; leží uvnitř rámu police), kusovník/cena/hmotnost i výrobní list ji berou podle skutečného rozměru kusu;
- **pod ní přibudou podpěrné profily 30×30** v ose hloubky mezi čelní a zadní podélník rámu police (T-styl: přední konec přes dvojici rohových spojek jako u příček držících šuplíky, zadní konec na čelo podélníku;
  délka = vzdálenost čel podélníků). **Počet:** pro každý rozpon desky mezi vnitřními plochami bočních příček police (a příčkou střední nohy – ta desku podpírá sama) `ceil(rozpon / 800) − 1`, rovnoměrně. Výsledek při hloubce 1000 (police 1):
  šířka 600 → 0, 1000 → 1, 1200 → 1, 1500 → 1, 1600 → 0 (střední noha), 2000 → 2, 2400 → 2, 3000 → 2 podpěry na polici (tabulka v `PODPERA_MAX_ROZPON` komentáři). **Mez 800 mm je PŘEDPOKLAD** (konstanta `PODPERA_MAX_ROZPON` v `api/stul_konfigurator.py`), Robert ji může změnit.
- hloubka ≤ 900 mm: beze změny (žádné podpěry, deska police široká jako stůl); výchozí konfigurace a zlatý test #577 identické.
**Práh 900 mm je nastavitelný (bot8 2026-10-04, Robert):** hloubka, nad kterou přibývají svislé profily bočnic, kratší deska police a podpěry (pod policí i pod deskou), je pravidlo `hloubka_stredni_profil` (výchozí 900, rozsah 400–1600 mm; ≥ 1500 = nikdy). Ukládá se do `app_settings` klíč `stul_pravidla` (JSON), edituje se v textovém poli v okně „Pravidla stolu" na stránce Generátor stolu (`GET/PUT /api/stul/pravidla`, PUT jen s oprávněním `nastaveni`/`upravit`, prázdné pole = výchozí). Generátor zůstává čistá funkce – `stul_api` načte hodnotu před každým požadavkem na stůl (cache 5 s; chyba/neplatná hodnota = zůstane poslední platná). Nevýchozí hodnota je součástí hashe konfigurace (`_prah_h`), výchozí hash nemění. Odpověď generátoru nese `hloubka_bocni_profil` (aktuální práh) a `info[].hloubka_mm`; texty oznámení (cs/en/sk) i montážní postup nesou aktuální číslo.
**Podpěry pod pracovní deskou (bot8 2026-10-04, `rules_version` 2026-10-04.1):** při hloubce > 900 mm přibudou stejné podpěrné profily i pod hlavní desku (mezi čelní a zadní příčku pracovního rámu, T-styl jako příčky šuplíků). Rozpony (`ceil(rozpon / 800) − 1`, rovnoměrně) se počítají po úsecích mezi bočními příčkami, příčkou střední nohy a příčkami šuplíků: **se šuplíky** jejich příčky desku podpírají (podpěra jen tam, kde zbývá úsek > 800 mm), **bez šuplíků** příčky zmizí a podpěry se doplní na stejných místech jako pod policí (nad nimi). Nové `info: {"kod": "deska_podpery", "podpery": N, "suplik": bool}` (vždy při hloubce > 900) → ve veřejném `resolve` `notices` `action: "info"` jen když N > 0; nová část 3D ovládání `podpery_deska` (veřejné id v `casti`).
**Odpověď generátoru:** nové pole `info: [{"kod": "police_podpery", "podpery": N, "kraceni_mm": 31, "urovni": K}]` (jen při hloubce > 900 a zapnuté polici). **Staff stránka** ho ukazuje pod cenou (`#info_police_podpery`).
**Veřejné `resolve`:** v `notices` přibyde `{"slot": "d", "action": "info", "message": "…"}` (texty cs/en/sk; „zkrátí o 31 mm z každé strany… přibude N podpěrné profily“ nebo „podpěrné profily nejsou potřeba“). UI mini-shopu (bot16) ať akci `info` ukáže jako
informativní řádek (ne jako „odebráno“). Nová část 3D ovládání má veřejné id `supports<N>` (podpěry police N). **Pozor:** výsledek pro hloubku > 900 mm se změnil (`rules_version` zvýšena na 2026-10-03.1) – uložená konfigurace z dřívější verze by se
nemusela shodovat; žádné objednávky s konfigurací zatím neexistují.

## Šuplíky vlevo, výška držáku PET, vzpěry automaticky nad 500 mm ramene (bot8 2026-10-04)

Změna se týká generátorů 01 (systém 30) i 02 (systém 40) a **mění výchozí stůl**: `w` 1280 mm (dřív 1200), 1 panel, hash/kód všech konfigurací je jiný (verze pravidel zvýšena, uložené konfigurace z dřívějška se nemusí shodovat).

Ve 3D tah `panelside` (úchyt na pravém okraji panelů, krok 1 mm, štítek ukazuje mezery od VŠECH noh: „od levé nohy“ / „od pravé nohy“, u dvou panelů „levý panel od …“ / „pravý panel od …“) a položka nabídky „Panely vrátit doprostřed mezi nohy“. Ve 3D tah `posth` na vrcholu stojky.

## Deska pokračuje dozadu, když se odeberou zadní stojky (bot10 2026-10-08, Robert: „stoly generator, když se odejmou zadní stojky (zkrátí), deska musí pokračovat dozadu překrýt svislé profily“)
- **Pravidlo:** přepínač **Zadní stojky** (`posts`, engine `stojky`) vypnutý = zadní nohy se zkrátí na výšku předních a pracovní deska **pokračuje dozadu o tloušťku profilu** (30 / 35 / 40 / 40 mm u systémů 30 / 35 / 40 / 45), takže její zadní hrana leží v rovině
  zadního líce zadních noh (jako po stranách, kde deska končí v rovině vnějších lic noh) a deska **překrývá zadní svislé profily i zadní příčku**. Se zapnutými stojkami je vše jako dřív (zadní nohy stojí ZA deskou, jejich přední líc = zadní hrana desky). Spodní police a SSE (41) se nemění.
- **Implementace:** `api/stul_konfigurator.py` `deska_zadni_pokracovani(SYSTEMY[sys], stojky)` (0 se stojkami / u SSE, jinak `profil_mm`) – použito třikrát: rozměr a poloha desky v jádru (`dZ`; přední hrana a šířka beze změny, střed o `dZ / 2` dozadu, `celek` pro cenu), meze polohy výřezů v normalizaci
  (`hloubka_desky`) a meze posuvníků výřezů v obchodě (`stul_shop.py`, `options.cut1d / cut1x …`). Záslepky na horních koncích zadních noh zmizí SAMY (konec profilu už není volný – dotýká se ho deska; `_volne_konce`), přibývá jen plocha desky (cena, kusovník, výrobní výpis).
- **Co se mění ještě:** ložiskové jednotky na desce se rozmístí podle nového obrysu (rozteč a okraj od hran), výřez zadaný až k zadní hraně sedí u nové zadní hrany (police pod ním s ním), výřezy a dělení desky u střední nohy fungují beze změny (obě poloviny se prodlouží).
- **Hash a verze pravidel:** `RULES_VERSION` se NEMĚNÍ (zůstává 2026-10-06.1) – stoly se stojkami jsou beze změny, takže jejich hash a kód STL-xxxxxx, karty `STUL-S*` ani zlaté testy se nehýbou; kanonický hash stolu BEZ stojek (kromě SSE) nese značku `_deska_zad` (= tloušťka profilu v mm; `kanonicky_hash` v `api/stul_glb.py`), takže jen on dostane nový hash a kód (jiný model a cena). Rozpracovaný košík nebo uložená nabídka se stolem bez stojek se starým hashem se tak při přepočtu pozná jako změněná.
- **Testy:** `scripts/2026-10-08_deska_pres_nohy/test_deska_pres_nohy.py` (viz README tamtéž): kandidát proti stavu před změnou na stejných výběrech (pseudonáhodný vzorek přes systémy 30 / 35 / 40 / 45).

## Výchozí konfigurace generátoru – admin tlačítko „Uložit jako výchozí“ (bot8 2026-10-05, Robert: „postav mi admin tlačítko v generátoru, kterým uložím konfiguraci jako výchozí“)
- **Uložení:** `app_settings.configurator_default_<id produktu>` = JSON úplný výběr (slot → ano/ne, číslo, text, null), normalizovaný `resolve` (ořez do rozsahů, doplnění klíčů); jeden záznam na generátor (karta systému 30 / 35 / 40 / 41). Tvar kontroluje `stul_api.vychozi_over` (nic se neořezává potichu: velké písmeno v názvu, pole jako hodnota, NaN, text nad 40 znaků, víc než 200 polí = `ValueError`).
- **Schéma** (`GET /api/shop/products/<id>/configurator`): `default_selection` = vestavěné výchozí (`stul_shop.vychozi_vyber`) přepsané uloženým (`slij_vychozi`: jen klíče, které schéma zná, a hodnoty stejného typu; co chybí – slot přidaný později – zůstane vestavěné), nové pole `default_saved` (bool). Vestavěné výchozí (`vychozi_vyber`, doplňování chybějících polí v `normalizuj`) se NEMĚNÍ: server-side normalizace nezávisí na uložené konfiguraci, mění se jen to, s čím se generátor otevře (stránka produktu, mini-shop, embed, interní stránka). `rules_version` beze změny, hash a kód úplného výběru také.
- **Routy** (jen admin, `nastaveni/upravit` jako uložení prostředí HDRI): `PUT /api/shop/products/<id>/configurator/default` s tělem `{"selection": {...}}` – výběr se znormalizuje a PŘEPOČÍTÁ: neplatná konfigurace = 409 s důvody (`errors`), chybný tvar / hodnota = 400, neznámý produkt = 404, bez přihlášení 401, bez práva 403; výběr mimo rozsah se ořízne jako v `resolve`; zápis + `audit_log` (`configurator_default`, update, id produktu, systém, kód, výběr). Odpověď `{default_saved, default_selection, hash, kod, notices}`. `DELETE` téže adresy = zpět na vestavěné (audit delete), odpověď `{default_saved: false, default_selection}`.
- **Čtení:** `stul_api.nacti_vychozi(product_id)` (cache 5 s jako u pravidel; chybná uložená hodnota = vestavěné výchozí, schéma nikdy nespadne); `uloz_vychozi` zapisuje (upsert) nebo maže.
- **UI** (`webapp/js/stul-host.js`, stránky Generátor stolu 01–04): okno „Výchozí konfigurace“ (jen admin) ve 3. sloupci – NE vedle 3D (výška řádku = vyšší sloupec, 3D by se prodloužilo): [Uložit jako výchozí] (pošle aktuální výběr modulu) a [Vrátit původní výchozí] (jen když je něco uloženo, podle `default_saved`); dvoukrokové potvrzení (první klik změní popisek na „Opravdu uložit pro všechny?“ na 6 s), po úspěchu se stránka načte znovu (modul vezme nové schéma, tlačítko „Výchozí hodnoty“ pak vrací na uloženou); „Vrátit původní“ vyčistí hash odkazu.
- **Důsledek pro odkazy:** odkazy, které nesou jen odchylky od výchozí (např. `#w=1800` nebo odkaz z mini-shopu), se po změně výchozí otevřou s NOVOU výchozí v ostatních polích; kód a hash úplné konfigurace (a tedy košík / objednávky, které ukládají úplný výběr) se nemění.
